## 2. 역할 분리 — 판정은 규칙, 설명은 LLM

| 층 | 하는 일 | 성질 |
|---|---|---|
| 규칙 상태기계(`state_machine.py`) | Target State(Zone, Held Object) 판정, 바뀐 것만 Event로 | 결정론: 같은 입력 → 같은 Event 열 |
| LLM(Gemma 4 E2B, `reporter.py`) | Event Log 텍스트로 SITREP·질의응답 | 이미지 입력 없음, 위험 판정·방송 판단 없음(ADR 0001) |

**왜 나눴나**
- 환각: SITREP 옆 근거 Event 원문(**Evidence**) 동시 출력 → 문장 한 줄씩 대조 가능
- 재현성: LLM이 위험 여부 결정 시 같은 장면에 다른 답 → 검증 불가
- 비용: Jetson 8GB 한 대에서 YOLO와 동시 실행 → 매 프레임 LLM 호출·이미지 입력 불가
- system 규칙(`COMMON_RULES`): 로그 사실만(없으면 '관측되지 않음') / 한국어 낱말만 / 위험 여부 판정 금지 / 2~3문장

> 노트 (40초): "핵심 결정은 역할 분리입니다. 판정은 규칙 코드가 하고, LLM은 그 결과를 설명만 합니다. 안내방송 문구도 규칙이 고르고 LLM은 쓰지 않습니다. LLM은 카메라 영상 없이 Event Log와 지금 장면 한 줄만 텍스트로 읽습니다. 그래서 SITREP 옆에 근거 Event를 같이 찍어 사람이 환각을 직접 확인할 수 있고, 판정은 규칙이라 카메라 없이 테스트로 재현됩니다."

**예상 질문**
- **왜 Gemma에 이미지를 안 보여 주나?** → 8GB에서 YOLO와 동시 실행이라 비용이 안 맞고, 이미지 입력은 출력 근거 추적 불가. 텍스트 Event는 Evidence로 대조 가능.
- **왜 LLM이 위험 판정을 안 하나?** → 같은 장면에 다른 답 가능, 검증 방법 없음. 판정은 규칙에 두어 결정론·테스트 가능, LLM은 설명 층.

## 3. 파이프라인 — 파일 12개, 세 줄의 흐름

![파이프라인](images/pipeline.svg)

- **메인 스레드(프레임마다)**: `camera` → `detector`(YOLO11n + 추적 id) → `state_machine`(`build_observations` → `step`) → `event_log` + `hud` → `announcer.handle_events`, 조립은 `main.process_frame`
- `event_log`: 메모리 목록 + `logs/events-YYYYMMDD-HHMMSS.jsonl` / `hud`: 박스·Target id·Zone·Held Object·FPS·Motion Level, 영어만
- **reporter 스레드**(Event·질문 때만): Gemma 4 E2B → SITREP + Evidence 터미널 출력, 질문 답만 Piper로 읽음
- **announcer 스레드**: 대기열 → 시작 때 합성해 둔 wav → aplay. 수동 방송은 재생 중인 소리를 끊고 맨 앞
- 그 밖: `motion`(Motion Level), `platform_config`(트랙별 경로·명령), `bench`(측정표)
- 한 코드 두 트랙: 개발·테스트는 Mac 사본, 제출본은 Jetson 전용 카메라 파이프라인(`camera.JETSON_PIPELINE`, 읽기 제한 시간 `JETSON_READ_TIMEOUT_MILLISECONDS` 3초)

> 노트 (45초): "메인 스레드는 매 프레임 검출, 상태 판정, 기록, HUD 그리기만 하고, 무거운 일은 작업 스레드 두 개가 맡습니다. reporter 스레드는 Gemma와 녹음·질문 답을, announcer 스레드는 안내방송을 냅니다. 방송을 따로 뺀 이유는 Gemma 생성이 방송을 늦추지 않게 하기 위해서입니다. 일은 큐에 넣고 메인 스레드는 바로 돌아오니까 생성이나 녹음 중에도 영상이 멈추지 않습니다. 개발은 Mac 사본에서 했고, 제출본 카메라는 Jetson 파이프라인 하나만 남겼습니다."

**예상 질문**
- **왜 별도 프로세스가 아니라 스레드인가?** → 가장 단순한 구조로 시작(단일 프로세스 + 작업 스레드 둘 + 큐). Jetson에서 이 구조로 FPS가 떨어지는지는 미측정, 떨어지면 별도 프로세스로 전환.
- **Mac 버전이 왜 있나?** → 보드 없이 흐름·로직 먼저 확인용. 제출본은 Jetson 기준.

## 4. Event 4종

| Event | 조건 | 임시값 |
|---|---|---|
| `appeared` | 보이는 상태 T 동안 지속 → 확정 프레임의 Zone·물체 담음 | `DEBOUNCE_SECONDS` = 1.0 |
| `gone` | Target이 T 동안 안 보임 → 마지막 Target State 담고 삭제 | 같은 T |
| `zone_changed` | 사람 박스 높이 / 프레임 높이 ≥ 기준 → `near`, 아니면 `far`. 새 값 T 유지 | `NEAR_HEIGHT_RATIO` = 0.5 |
| `object_changed` | 물체 박스 중심이 사람 박스 안 → 보유. **물체 종류별로 따로** 디바운스 | `HELD_OBJECT_CLASS_NAMES` 4종(knife·bottle·cell phone·backpack) |

- Event 필드 5개 고정: `timestamp`, `target_id`, `kind`, `before`, `after`

> 노트 (25초): "Event는 네 종류뿐입니다. 디바운스는 프레임 수가 아니라 초 단위 T 하나라서 Gemma 생성 중 FPS가 떨어져도 확정까지 걸리는 시간이 같습니다. 물체는 종류별로 따로 걸러서 칼 검출이 깜빡여도 휴대폰 변화는 제때 기록됩니다. 물체를 들었다고 인정된 Event가 안내방송의 근거가 됩니다."

**예상 질문**
- **디바운스를 왜 초 단위로 했나?** → 프레임 수로 세면 FPS 저하 때 확정 지연. 상태기계는 시계를 직접 읽지 않고 시각을 인자로 받음 → 같은 입력 시퀀스로 테스트 재현.

## 5. LLM 트리거 2경로

**LLM 호출 경로 둘뿐** (매 프레임·주기 호출 없음)
1. Event 발생 → SITREP(Event Batch + Snapshot, 터미널만)
2. 키 `v` → 5초 녹음 → Whisper → Spoken Question(답은 터미널 + Piper). 음량 RMS < 500(`SILENCE_RMS_THRESHOLD`) → Gemma 호출 없이 "질문을 듣지 못했습니다."

- 키 `1`·`2`·`3`은 LLM을 부르지 않는다 — 수동 안내방송(6장)
- 질문 근거: 최근 60초(`QUESTION_WINDOW_SECONDS`) Event + Snapshot
- 우선순위: 질문 > 대기 중 Event Batch. 생성은 한 번에 하나, 생성 중 쌓인 Event는 다음 SITREP 한 번에

> 노트 (20초): "LLM은 Event가 생기거나 운용자가 말로 물을 때만 불립니다. 안내방송은 LLM을 거치지 않습니다."

**예상 질문**
- **왜 상시 듣기가 아니라 키 + 5초 녹음인가?** → 상시 듣기는 스피커 소리·잡음에 오작동. 무음이면 Whisper가 글을 지어냄(조용한 방 녹음에서 확인) → 음량 검사로 차단.

## 6. 안내방송 — 스피커는 표적에게

- 청중 전환: SITREP은 운용자(터미널), 스피커는 표적(안내방송)

| 문구 | 자동 조건 | 키 |
|---|---|---|
| `put_down` "들고 있는 물건을 바닥에 내려놓으세요." | 물체 보유 Event(`object_changed`·`appeared`), 같은 문구 10초(`REBROADCAST_SECONDS`, 임시값) 간격 | `1` |
| `hands_up` "양손을 펼쳐 어깨 위로 드세요." | 없음(수동) | `2` |
| `hold_still` "그 자세를 유지하세요." | 없음(수동) | `3` |

- 깜빡임 거르기 = 상태기계 1.0초 디바운스 그대로(1초 안에 사라진 물체는 Event가 아니라 방송도 없음)
- 문구 wav는 시작 때 Piper로 한 번 합성·캐시 → 방송은 재생만(Piper는 호출마다 프로세스를 새로 띄워 느림)
- 별도 스레드: Gemma 생성이 방송을 늦추지 않음. 수동 방송은 재생 중 소리를 끊고 맨 앞
- 판단은 규칙, LLM은 쓰지 않음(ADR 0001 유지)

> 노트 (35초): "스피커의 청중을 바꿨습니다. SITREP은 운용자가 터미널에서 읽고, 스피커는 카메라 앞의 표적에게 고정된 안내방송을 냅니다. 표적이 물건을 들었다고 인정되면 자동으로 '들고 있는 물건을 바닥에 내려놓으세요'가 나가고, 나머지 두 문구는 운용자가 키로 냅니다. 깜빡임은 상태기계의 1초 디바운스가 이미 거르고, 문구는 시작할 때 미리 합성해 두어 방송 때는 재생만 합니다. 어떤 문구를 낼지는 규칙이 정하고 LLM은 관여하지 않습니다."

**예상 질문**
- **왜 손 숨김·항복은 자동이 아닌가?** → 모델 2개(Pose·Hand) 추가의 RAM·FPS가 미측정이라 이번 범위에서 제외. Project01 규칙 이식이 다음 단계.
- **오방송 위험은?** → 1초 디바운스 + 10초 재방송 간격(둘 다 임시값, 카메라 실측으로 정할 것). 문구는 고정이라 틀린 문장이 나올 수 없고, 운용자가 키로 바로 정정 방송 가능.

## 7. 시연

캡처: Jetson 실행 후 삽입

동작 순서(시연 리허설 순서 그대로)
1. 화면 밖 → 진입 → `appeared`, 터미널 SITREP + Evidence / 접근 → `zone_changed`
2. 병·휴대폰 듦 → `object_changed` → 1초 뒤 스피커 "들고 있는 물건을 바닥에 내려놓으세요."
3. 키 `2` → "양손을 펼쳐 어깨 위로 드세요." (수동)
4. 키 `v` → "지금 몇 명 있어?" → 답 음성 / 소리 중 `v` 재입력 → 끊김·녹음
5. 물건 내려놓고 화면 밖 → `gone` / `q`

- 볼 것: 터미널 Event 한 줄 → SITREP + Evidence + Snapshot, [방송] 줄, HUD `#id near bottle` 라벨, FPS·MOTION

> 노트 (75초): "직접 카메라 앞에서 보여 드리겠습니다. SITREP은 터미널에서 보시고, 스피커에서는 표적에게 하는 안내방송이 나옵니다. 들어오면 잠깐 뒤에 appeared가 찍히고 SITREP과 근거 Event 원문이 터미널에 나옵니다. 문장과 근거가 한 줄씩 맞는지 확인할 수 있습니다. 병을 들면 1초 뒤 '들고 있는 물건을 바닥에 내려놓으세요'가 스피커로 나오고, 키 2를 누르면 '양손을 펼쳐 어깨 위로 드세요'를 수동으로 냅니다. 마지막으로 말로 질문하고, 답이 나오는 중에 v를 다시 눌러 재생이 끊기는 것까지 보여 드리겠습니다."

**예상 질문**
- **SITREP이 로그에 없는 말을 하면?** → system 규칙(로그 사실만, 없으면 '관측되지 않음')이 1차, 터미널 Evidence 대조가 2차.
- **재생 중에 `v`를 누르면 왜 끊나?** → 끊지 않으면 스피커 소리가 마이크에 섞임. 녹음 질문 먼저 넣고 그다음 재생 끊음(`submit_spoken_question` → `stop_playback`).
